# UniProof Demo / Devpost Checklist

## Production

- [ ] `https://uniproof-beta.vercel.app` opens without authentication.
- [ ] Research, Compare, and Guide navigation works on desktop and mobile.
- [ ] No browser console/CSP error appears in the recorded flow.
- [ ] Do not perform repeated live Research retries merely to get a prettier demo result.

## Recording privacy

- [ ] Use invented applicant/profile values only.
- [ ] No `.env`, terminal, provider dashboard, Vercel environment value, auth cookie, or private account screen appears.
- [ ] No real academic record, email, document, identifier, or secret appears.
- [ ] Browser bookmarks/tabs/notifications do not expose unrelated private information.

## Content to demonstrate

- [ ] Problem: university information is fragmented and AI answers can hide evidence quality.
- [ ] Research: supported target, evidence status, exact evidence/source inspection, explicit unknown/incomplete handling.
- [ ] Compare: two compatible targets, relative priority sliders, deterministic coverage/fit, no prestige ranking.
- [ ] Guide: invented profile, published-requirement assessment, checklist/official links, no admission-probability claim.
- [ ] AI architecture: structured extraction/reconciliation followed by deterministic evidence policy.
- [ ] Privacy: applicant profile values do not enter the Research/provider request.
- [ ] Production controls: nonce CSP, bounded Research execution, WAF rate limit.

## Video

- [ ] Final public video is approximately three minutes; preferred scripted target is 2:20–2:35 before natural pauses.
- [ ] Audio is understandable and on-screen text is readable.
- [ ] Product/problem/meaningful AI integration are all visible.
- [ ] If deterministic release screenshots are edited into the video, present them as product screenshots rather than claiming they are the live response currently executing.
- [ ] Final video URL is publicly accessible to judges without sign-in.

## Devpost before final submit

- [ ] Re-open current Pixel Forge overview/rules/schedule immediately before submission.
- [ ] Confirm live app URL and public GitHub URL.
- [ ] Confirm `LICENSE` remains public and complete.
- [ ] Paste/review `docs/submission/devpost-draft.md` against the actual final video.
- [ ] Check title, tagline, judging alignment, technologies, and video URL.
- [ ] Confirm no unsupported claim that hosted Auth/save is enabled.
- [ ] Confirm no claim that the final bounded live-provider smoke returned evidence; the three-call release budget was exhausted and the last call returned an explicit incomplete dossier.
- [ ] Obtain final user authorization for the exact Devpost submission.
- [ ] Only then click the final Devpost submit control.
